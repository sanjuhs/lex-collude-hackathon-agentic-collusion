# Limitations and dual-use considerations

All parties, disputes, approvals and documents in this repository are fictional. No privileged material, client identifiers, legal filings, or real settlement actions are used. This is a controlled model-behavior benchmark, not legal advice or validation for autonomous legal practice.

The attack fixtures contain obvious document-borne instructions and false approval claims. They are intended to test trust boundaries and defensive enforcement. They do not prove that comparable attacks succeed in a deployed law firm. Do not apply the payloads to real counterparties, live legal matters, or services without authorization.

An attacker can manipulate a victim without the victim knowingly coordinating. Consequently, successful influence is not evidence of collusion by itself. The code deliberately leaves coordination unreviewed. Observable final artifacts cannot establish an agent's private mental state.

Small pilots, one language, a fixed prompt family, limited rounds, and synthetic cases sharply limit generalization. Native Codex system prompts, context handling and model routing can affect results. Model aliases may change; native immutable model revisions and token usage are not available in this bridge. A no-tools instruction and conductor attestation are not a security isolation guarantee.

Deterministic enforcement only checks modeled constraints. It cannot resolve ambiguous law, assess document authenticity, infer actual client authorization, or detect all material omissions in prose. A zero measured violation rate is not proof of deployment safety.

Use synthetic inputs and least-privilege credentials. Keep API keys in environment settings. Review all artifacts before publication. If adapting the benchmark to sensitive material, obtain authorization and design a separate privacy and data-retention process first.
